# Промпт для нового чата

**Что приложить к первому сообщению:** `MediaHub-handoff.zip` (весь проект, внутри `CLAUDE.md` и `docs/HANDOFF.md`). Больше ничего не нужно; для шага 4 ещё страницы-образцы сайтов.
**Что вставить в текст:** блок между линиями ниже, а в конце одну из строк «Задача».

---
Ты продолжаешь разработку MediaHub (локальный загрузчик + библиотека на Python/SQLite, интерфейс в браузере). Отвечай по-русски, коротко.

Порядок:
1. Распакуй приложенный zip (`unzip`; для `.7z` есть `tools/un7z.py`, 7-zip в контейнере нет). Сети нет.
2. Прочитай ТОЛЬКО `CLAUDE.md` и `docs/HANDOFF.md`. Остальной код не читай целиком: `grep -n` и срезы по 20–40 строк. Не используй `cut -c` и `head -c` (ломают кириллицу).
3. Прогони базу тестов в фоне (`python tools/offline_tests/run.py tests`, если нет pytest) и читай только хвост. Ожидается **505 passed, 6 skipped**. Число падать не должно.
4. Работай шагами: для новой логики сначала чистые функции в отдельном модуле и тесты (с контролем «без реализации тест падает»), затем минимальная вставка в `app.py` и интерфейс. Доступность интерфейса обязательна (правила в `CLAUDE.md`).
5. Образцы сайтов и страниц только от пользователя. Если образца нет, спроси и остановись, не выдумывай селекторы.
6. В конце шага: полный прогон, обновить статус в `docs/HANDOFF.md` (раздел 5), собрать zip в `/mnt/user-data/outputs`, ответить: что сделано, что проверено, что НЕ проверено, что дальше. Без воды.
7. Доступ с других устройств по Wi-Fi уже сделан (HANDOFF, раздел 7): не переделывай, только расширяй по просьбе.

Навыки и плагины (использовать, если они доступны в этой среде; нет такого, пропустить):
* Экономия: `ponytail` (наименьшее изменение и короткий ответ) на всей кодовой работе; `token-saver` и `token-saver-snapshot` (если среда Claude Code/CodeBuddy: снимок диалога при длинной сессии); `dispatching-parallel-agents`/`subagent-driven-development` только если есть субагенты и задачи независимы.
* Качество: `brainstorming` (до новой функции, 5 строк, не больше), `writing-plans` → `executing-plans` (для шагов из нескольких частей), `test-driven-development`, `systematic-debugging` (при падении теста: сначала причина, потом правка), `verification-before-completion` (не писать «готово», пока не показан хвост полного прогона), `requesting-code-review`/`code-review` и `testing-strategy` (перед сборкой zip), `architecture`/`system-design` и `tech-debt` (для шага 8).
* Интерфейс: `accessibility-review` и `design-critique` для каждого нового экрана, `ux-copy` для подписей и ошибок, `frontend-design`/`design-system` только если меняется внешний вид.
* Память проекта: `claude-md-improver`/`revise-claude-md` в конце шага (обновить `CLAUDE.md`), `skill-creator` один раз: создать навык `mediahub` из HANDOFF, чтобы будущие чаты стартовали без вложений.
* Не подключать: SEO-плагины (`searchfit-seo:*`), Vercel (`833bb33c…`), Next.js, `docx`/`pptx`/`xlsx`/`pdf`, `morning`, `import-memory`. Они не относятся к проекту, а описания включённых навыков занимают контекст в каждом чате (лучше отключить их в настройках).

## Как это экономит контекст (коротко)
* Новый чат начинается с ~150 строк (`CLAUDE.md` + `HANDOFF.md`) вместо чтения тысяч строк кода и истории.
* Один шаг плана на чат: контекст не накапливает прошлые шаги.
* Чистые функции и урезанные фикстуры дают короткие тесты и короткие выводы.
* Отключённые навыки не добавляют свои описания в каждый запрос.
