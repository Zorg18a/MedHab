# MediaHub. Этап 1: основа доступности (спецификация дизайна)

Дата: 2026-11-08. Стандарт: WCAG 2.1 AA. Статус: на проверке.

## 1. Цель и контекст

MediaHub — локальное приложение (`app.py`, http://127.0.0.1:8765) с UI в одном `index.html` (438 строк плотного кода, `onclick` внутри строк HTML), читалкой `reader.html` и расширением браузера. Аудит доступности выявил 22 пункта (1 критический, 13 серьёзных, 8 мелких).

Весь проект разбит на 5 этапов, каждый со своей спецификацией, планом и реализацией:

1. **Основа доступности** (этот документ): центр уведомлений, режимы отображения, горячие клавиши, правка всех 22 пунктов аудита, переход на ES-модули.
2. Читалка 2.0 и плеер (субтитры, «Продолжить»).
3. Вкладка «Обновления» и правила «Входящих».
4. Очередь загрузок (пауза, повтор, порядок, лимит по расписанию).
5. Коллекции, статусы, скрытие обложек.

Критерий готовности любого этапа: все новые элементы проходят чек-лист WCAG 2.1 AA (раздел 8).

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Фронтенд | ES-модули без сборки; `app.py` отдаёт `/js/*` как статику |
| Хранение режимов отображения | `localStorage` браузера (ключ `mh.prefs`) |
| Центр уведомлений | Журнал в памяти страницы (50 записей), тост 8 с с паузой при наведении и фокусе |
| Горячие клавиши | Последовательности `g`+буква, переключатель в настройках, без переназначения |

## 3. Вне этапа

Читалка 2.0, плеер, обновления, правила «Входящих», очередь, коллекции, скрытие обложек. Серверные таблицы и протокол с расширением не меняются. В `reader.html` и `extension/popup.*` вносятся только мелкие правки из аудита (подпись селекта глав, токены).

## 4. Структура

`app.py`: один новый маршрут, отдающий файлы из `js/` и `css/` (расширения `.js`, `.css`; защита от выхода за каталог; те же проверки Host и Origin, что у остальных маршрутов).

| Модуль | Ответственность |
|---|---|
| `js/main.js` | Запуск, роутинг по `#hash`, `document.title` вида «Раздел — MediaHub», фокус на `h1` раздела с `tabindex=-1` |
| `js/core/api.js` | `api()`, `poll()`; перехват сетевых сбоев (раздел 6) |
| `js/core/dom.js` | `$`, `qa`, `esc`, делегирование событий через `data-action` вместо `onclick` в строках |
| `js/a11y/announce.js` | `announce()`, `notify()`, журнал, панель журнала |
| `js/a11y/prefs.js` | Чтение и запись режимов, выставление `data-*` на `<html>` |
| `js/a11y/keys.js` | Горячие клавиши, справка `?` |
| `js/ui/chip.js`, `switch.js`, `dialog.js`, `field.js`, `progress.js`, `tabs.js`, `cardbtn.js` | Общие элементы с правильными ролями, состояниями и клавиатурой; `field.js` содержит `fieldError()` |
| `js/views/library.js`, `add.js`, `inbox.js`, `downloads.js`, `games.js`, `settings.js` | Разделы и диалог «Добавить», перенесённая логика с исправлениями |
| `js/legacy.js` | Временно: прежний inline-скрипт, из которого разделы переносятся по одному; к концу этапа пуст и удаляется |
| `css/tokens.css`, `css/base.css`, `css/components.css` | Токены, база, компоненты |

`index.html` остаётся каркасом: `<head>` с пятистрочным inline-скриптом (применяет режимы до отрисовки), ссылки на CSS, `<script type="module" src="/js/main.js">`, разметка `aside/nav/main`, skip-link «Перейти к содержимому» первым элементом `body`.

## 5. Режимы отображения и токены

Схема `mh.prefs` (JSON): `{scale: 100|125|150, contrast: "normal"|"high", theme: "dark"|"light"|"system", targets: "normal"|"large", keys: true|false}`. Значения по умолчанию: 100, normal, dark, normal, true.

`prefs.js` выставляет на `<html>`: `data-scale`, `data-contrast`, `data-theme` (для `system` вычисляется из `prefers-color-scheme`), `data-targets`. Размер текста задаётся `font-size` на `:root`; все размеры шрифтов в CSS переводятся из px в rem. Контраст и светлая тема реализуются переопределением токенов под `[data-contrast=high]` и `[data-theme=light]`: `--line`, `--line2` (границы не слабее 3:1 к фону), `--mute`, `--ph` (placeholder не слабее 4.5:1). Режим `[data-targets=large]` задаёт минимум 44×44 px для кнопок, чипов и переключателей. `prefers-reduced-motion` сохраняется.

Если `localStorage` недоступен, используются значения по умолчанию, один раз показывается уведомление.

## 6. Поток данных и ошибки

**Режимы.** Настройки пишут в `localStorage`, обновляют `data-*` и вызывают `announce("Размер текста: 125 %")`.

**Уведомления.** `notify(text, {kind: "info"|"error", action?: {label, fn}})`: запись в журнал (последние 50), тост 8 с (пауза при наведении и фокусе, `Esc` закрывает), дубль в одну `aria-live=polite` область; ошибки идут в `assertive` и не гаснут сами. Действие тоста доступно и из журнала. Журнал открывается кнопкой-колокольчиком в боковой панели и по `g`+`n`, это `<dialog>`.

**Прогресс загрузок.** Визуальные полосы обновляются каждую секунду. Скринридеру сообщаются начало, завершение, ошибка и шаги по 25 %. У полос `role=progressbar` и `aria-valuenow`; `role=status` с нижней полосы загрузок снимается, она становится ссылкой на «Загрузки».

**Ошибки форм.** `fieldError(поле, текст)`: `aria-invalid="true"`, `aria-describedby` на сообщение под полем, фокус на поле, дубль в live-область. Заменяет тосты вида «Вставьте ссылку…».

**Смена раздела.** `route()` ставит заголовок и переносит фокус на `h1` раздела.

**Потеря связи.** `api()` перехватывает сбой, показывает один постоянный `assertive`-статус «Связь с MediaHub потеряна», замедляет опрос до 5 с; при восстановлении сообщает «Связь восстановлена».

**Панели и диалоги.** Панель игры становится `<dialog>` с прежней анимацией; фокус возвращается на карточку, фон недоступен (`inert`), `Esc` закрывает. Общий помощник `dialog.js` запоминает элемент, открывший диалог.

## 7. Горячие клавиши

Активны при `prefs.keys = true`, игнорируются в полях ввода и при нажатых Ctrl, Alt, Meta. Таймаут последовательности 1.5 с.

| Клавиши | Действие |
|---|---|
| `g` затем `l` / `i` / `d` / `g` / `s` | Библиотека / Входящие / Загрузки / Игры / Настройки |
| `g` затем `n` | Журнал уведомлений |
| `j` / `k` | Следующая / предыдущая карточка в сетке |
| `/` | Поиск в текущем разделе |
| `?` | Справка по клавишам (`<dialog>`) |

Переключатель «Горячие клавиши» в Настройках. Раздел справки сообщает о возможности отключения (WCAG 2.1.4).

## 9. Тесты и приёмка

Папка `tests/` (не входит в поставку):

1. **`contrast.py`**: читает токены, считает пары «текст/фон» и «граница/фон» для 4 сочетаний (тема × контраст), падает ниже 4.5:1 для текста и 3:1 для границ и элементов интерфейса.
2. **Playwright** (уже в `requirements.txt`): открывает 5 разделов × 4 сочетания, подключает локально лежащий `tests/vendor/axe-core`, требует 0 серьёзных и критических нарушений; проверяет зум 200 % без горизонтальной прокрутки; проверяет размеры целей в режиме «крупные цели».
3. **Обход клавиатурой** (Playwright): Tab проходит все интерактивные элементы, фокус виден, диалоги удерживают и возвращают фокус, горячие клавиши и переключатель работают.
4. **Lint-скрипт**: у каждого `input/select/textarea` есть имя; чипы имеют `aria-pressed`; нет `onclick` на неинтерактивных элементах и `a href="#"`.
5. **Ручной чек-лист** (10 сценариев, NVDA с Firefox и Яндекс Браузером): настройки, фильтры, добавление, загрузка, панель игры, уведомления, смена раздела, горячие клавиши, потеря связи, режимы отображения. Результат в `docs/a11y-manual-stage1.md`.

**Готовность этапа 1:** все 22 пункта закрыты и каждый ловится указанной проверкой; axe без серьёзных и критических нарушений; обход клавиатурой проходит; ручной чек-лист подписан.

## 10. Порядок миграции и риски

Порядок: `core` и `css/tokens` → `a11y/*` → `ui/*` → разделы по одному (Настройки, Библиотека, Загрузки, Входящие, Игры) → правки читалки. После каждого раздела запускается Playwright-проверка. Старый `index.html` остаётся рабочим, пока раздел не перенесён.

Риски:
- перенос px на rem и замена `onclick` затрагивают весь UI, что снимается переносом раздел за разделом и проверкой после каждого;
- `<dialog>` для панели игры требует сохранить анимацию и клик по затемнению (решается обработчиком клика по `::backdrop`);
- `axe-core` кладётся в `tests/vendor` вручную, поскольку сеть у разработчика может быть недоступна.
